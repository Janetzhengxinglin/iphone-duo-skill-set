# 审查报告的视觉呈现与验收

本文件统一交付方法，不改变平台规范、合法结论类型或截图审查范围。图数、列数和例图尺寸按当前内容调整，不把历史报告的页名、四类问题或四张示例写成上限。

## 简短、对应、图为主

标题下最多一句范围或结论；完整统计、设备未知项、采集/去重过程与来源限制留后台。每个问题点用一句话说清具体表现与主要影响，依据摘要简短，避免重复制作过程。

官方区优先使用直接对应当前问题的官方抽象图解：文字排布、图文质量对照、媒体裁切、可用区域或容器关系等。完整示例 App/UI Kit 页面只在需要具体结构时补充。正确布局的正向图也可以，不要求示例出现同一种错误；仅因它也是折叠屏不能采用。

每张图在图外标题明确对应问题类型/编号，配一句说明和可点击来源。只有确实对应多项时才共用，逐项保留图→条款→审查项映射，不把一张通用图当成所有问题的依据。必须看过具体原图或 Frame；保留原比例与内容，不拼成假官方原图，不重绘冒充官方。抽象官方图片按原图交付；UI Kit 原生 Frame 可复制时仍保留原生图层，实际复制受限才使用核实过的原图。

例图解释规范，App 证据证明问题。示例中的分栏、间距、字体或颜色不自动成为强制要求；归档官方设计资源只作适用的参考，记录版本/边界并链接当前判断依据。

## 对齐、标号与尺度

默认左对齐报告标题、区标题及每张参考卡内的图、说明、链接。用户明确指定其他对齐时保持统一边线关系。同一列 App 图框使用共同原点和显示宽度，原图比例不变；标号换侧不能导致其中一张图单独平移。

预留左右侧栏，编号可按目标位置选择左、右、上或下侧。圆号与数字必须在截图外且在导出容器内，短引线就近连接实际位置并避开正文和控件；不能固定左侧或为了侧边要求让长线绕整张页面。标号与位置框保持原生可编辑。

官方图是适中参考，不抢过 App 证据。按原图比例、数量及可读性选择紧凑布局，不硬固定图数/列数，不拉满整个画板，也不能缩到看不清。说明卡的既有字号、颜色和内部结构保持一致；画板高度只随必要内容增加。

## 底部汇总与去重

将本平台允许且本次选择保留的全部审查项核对到“原始发生状态→同页分组→底部代表图”。不同业务页、姿态/窗口、组件或代表图未覆盖的位置须保留必要截图，不按模板容量截断。同页同组件同异常仅滚动或重复进入时各区保留最清楚的代表图，全部来源与分组理由留后台。

缺少逻辑页面/组件身份或图像核实不能自动合并。候选检查的未知、加载、运动或未成立状态不自动升级为问题；安卓明确保留的待核实/展示观察与已确认项分开，苹果仍只使用其当前审查协议允许的结论。汇总完整性只说明本次记录一致，不保证不存在漏判或整个 App 已覆盖。

## 真正验收

结构检查之外，实际查看清晰分区/图卡与标注：图文对应、边线对齐、尺度适中、原比例、图外编号/短引线、链接及可读性都要通过。整张报告缩略图只验总布局，不能替代细节检查。

未改动预览可核对本轮实际节点/内容与 hash 未变后继承同一版本已完成 QA，记录源验收与本轮映射；受影响预览必须新读并按图片预算记账。任何缺图/漏映射、标号遮正文或只有结构通过的情况都不标发布成功。这不减少两轮全页面原图审查。

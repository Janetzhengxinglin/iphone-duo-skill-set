# 报告约定

报告只展示当前内容选择中的问题页面：显示缺陷和可选的平台指导差异。指导差异标“建议调整”，与显示缺陷共用一次说明区和一个页面汇总区；无机型因果证据的通用显示问题标明“通用显示问题”，不认定 Duo 独有。

问题发现、同页问题、问题类型、问题页面和必要代表图均不限数量。归组以本次完整发现为准，不能预设四类或沿用历史类型作为检查上限。同类同号仅减少重复说明，不减少发现、标注位置或发生页面；不同现象不为了压缩数量强行归组。页面统计、发现条数及问题类型数不可混用。

模板限制的是展示结构，不是问题容量。空间不足时扩展说明区、增加代表图或汇总行并延长画板；标签拥挤时拆分同一页的标注视图，保留全部标注与原有编号，不丢弃低优先级或超出首屏的问题。所有已成立且在选择范围内的发现都须展示。

固定顺序：流程名/姿态与简短统计 → 苹果官方规范示例 → App 问题示例与集中说明 → 问题页面汇总。官方示例保持源内容：Figma 的 UI Kit 示例优先使用原生 Frame／组件实例，视频与 HIG 图片保留原图；飞书可用完整导出图。标题在示例上方醒目展示；不得自行加引线、标签或改造布局。官方规范区与 App 问题区独立、前后排列，不混在同一个示例图网格内。问题示例区左侧放去重的受审代表截图，右侧按编号集中说明；一张图不能覆盖全部问题时使用多张，不为每类重复建立一张画板。下方统一展示有发现的页面，只保留页面名和同类同号的标注，不重复正文。无发现仅简短结论。无问题图与完整检查留后台，不建全部页面展示区。数字表示问题类型，不显示原始截图 ID/时间点，不重复图下“问题编号”。

统计以受审页面状态为单位，三类互斥：有显示缺陷的计“需修改”；没有显示缺陷、只有指导差异的计“仅有建议项”；其余计“检查通过”。同一页同时有缺陷和建议只计需修改。不要用“问题数”指页面数，或把“检查通过”表述成全面功能验收。报告只展示用户选择范围内的发现。

每组只写问题类型、问题点、官方依据。问题点使用“问题点：”标签，描述截图里的具体异常；官方依据使用独立链接标题及简短标准摘要，清楚区分标准与实际问题。中文摘要精简准确；官方依据独立段落、蓝色下划线 URL，定位章节/视频时间。不写“中文翻译”“适用说明”，不写操作指令或选帧过程。不同现象多图展示，不能拼大量逐页观察。

assets/report-style.json 维护深蓝背景、浅灰蓝卡、橙色#F2A311白字外侧数字、红框引线、原图比例。官方示例使用“醒目的官方规范标题＋未经改动的原生 Frame／原图＋来源链接”形式。只有 App 问题截图添加问题编号和红框。模板链接只在后台配置中。模板训练不改规则。

需要由脚本输出官方示例时，在任务目录提供 official-references.json。视频／HIG 图片使用 {"figures":[{"source_type":"official_video","image":"本地官方原图路径","url":"定位章节或时间的官方链接","caption":"必要的场景说明"}]}；HIG 的 source_type 为 `hig`。

UI Kit 项使用 `source_type: "apple_ui_kit"`、`url`（苹果官方来源）、`resource_url`（定位已核实源 Frame 的 Figma 链接）；可加 `image` 作为完整导出预览。Figma 输出不强制生成导出图；飞书输出需要图。caption 可省略。脚本保留 `figma_delivery.preferred = "native_frame"` 和 `figma_delivery.native_source` 的源文件／节点信息；导出图片不会改变原生交付优先级。资源来源、版本和核实记录留本次任务后台，不写入 skill。

无匹配示例时可省略规范区；“没有匹配资源”与“已有资源但复制受限”分开记录。后者执行图片替代规则，不能当作没找到资源。

report.json 是展示白名单；review/capture/intake 为后台。两个发布渠道及内部 HTML 均从同份报告数据生成。校验脚本不替代目视复核和中文摘要准确性验证。

官方示例的选取范围与核实要求见 figma-output.md「官方示例的来源与选择」。official-references.json 的 url 指向苹果官方原文／资源页；引用 UI Kit 时可另加 resource_url，定位经核实的官方资源 Frame。核实记录留在任务后台。

## 统一样式与示例去重

所有姿态共用 assets/report-style.json 的 unified-report-v2；不能根据录屏、历史报告或新增问题临时改变排版、卡片颜色、字体、间距和编号。官方规范示例独立在前；App 示例只设一个区域，左侧代表图网格、右侧一次性列完全部说明卡；其后一个完整问题页面汇总。不额外拆“新增问题”说明区。

问题示例每个编号只归属一张代表页面，优先选能够同时解释多个编号的页面，再为未覆盖编号补图。代表图只标注分配给该图的编号，避免同一编号在不同示例页重复出现。同一张图内同编号可指向多个相关位置。这个限制只减少重复示例，不减少问题类型、发现或汇总页面。问题页面汇总枚举全部问题状态，并标出每页所有成立编号。

Figma 采用固定画板与两栏尺寸、示例每行三列、汇总每行五列、统一说明卡和字号；具体值读 style.figma。截图按原比例适配图框，不拉伸；不同姿态截图高度可以不同。官方源内容保持未经加工；Figma UI Kit 示例按原生 Frame 交付规则执行。说明卡统一 #E8EDF4，正文 #172033；官方依据 #065CE4 下划线并显示 ↗，与问题点留独立段落间距。示例标号直径 56，汇总标号直径 64，均为 #F2A311 圆底白字。

完成前校验：每个编号恰好归属一张示例图；全部问题页与完整标注未丢失；三份布局配置一致、全部说明卡颜色一致；官方依据可点击；原图比例、文字边界、编号与引线无错位。输出材料不展示这些制作要求。

## 批量结果的回查

问题归类在逐页、逐实例检查完成后进行；归类和代表图去重不能删除页面发现。已确认的历史问题与对应证据映射保存在项目运行目录，发布前用该映射回查新批次：相同问题仍存在时必须保留，有变化时重新判定并记录理由。历史页面编号、数量、截图和发现不写入通用 skill。

清晰示例应同时展示缺陷与造成裁断或覆盖的边界。表格缩略图难以辨认时，补充局部放大；不能用模糊示例替代原始截图核对。检查项填齐和结构验证通过只表示记录完整，不表示像素审查正确。

代表图优先选缺陷清晰、无无关弹层干扰的稳定页面。同页无弹层截图能说明底层缺陷时，优先用它；同类示例去重不能牺牲证据清晰度。红框和引线只圈实际异常对象及其交界，不把正常弹窗按钮、遮罩或覆盖区域圈成错误。必须使用有弹层的截图时，正常覆盖与所报异常应能明确区分；不能清楚区分时更换示例或不以该图举证。

发布前做一次图文对应检查：只看示例、红框和问题点，读者应能准确识别同一异常。正文正确但标注指向正常行为也属于交付错误。更换示例后同步证据映射、坐标和页面名，保留实际发生页，核对同类编号仍只归属一个代表页面。

# 集中批量审核

两端使用相同的公开执行流程；平台规则、姿态／窗口字段和逐项判定格式保持各自契约。默认由主智能体按完整业务流程连续工作，不按图片张数拆任务。

1. 先建立完整素材清单，核对重复链接、连续片段及跨姿态关系。每份独立录屏顺序解码，默认每 1 秒选择一帧，最后一个采样区间逐帧保留以覆盖末帧及尾部短状态，保留实际源帧时间、全部无损候选和 hash。候选拼图仅用于识别状态；连续完全相同帧可折叠首尾预览，仍展开索引分类全部候选。逐段核对录屏的完整时间范围，快速变化、短暂提示、键盘、弹层及疑似遗漏区间补看原视频或加密补帧。默认采样不是验收边界，不因预算把全程采样再放疏。
2. 分类和选帧完成后统一 finalize；选中候选直接复用对应的无损源帧，不重新跳转取得另一帧。补选任意时间点使用顺序解码。原图不覆盖，裁边／脱敏使用平台采集能力并另存副本。完整 capture 和必要补帧齐备后交接，候选阶段不先挑问题页。
3. 用采集 skill 的 scripts/review_sheets.py CAPTURE OUTPUT --pages-per-sheet 4 生成清晰整页拼图和 manifest；可改成 2 或 1 页。格位索引保留页面 ID、证据 ID、源路径与 hash；拼图不代替原图证据。逐页巡检全部可见组件，同时确认截图比例、边界、稳定性、裁边／脱敏和适配。文字、图标或边界不清以及疑点打开该页原图／有坐标映射的细节，不把多页强塞进低清拼图。
4. 每次读取后保存真实页面／组件观察，再批量展开本平台的正式逐项检查与问题记录；没看过的项不能从问题列表反向填通过。阶段切换、流程结束或中断保存检查点，保留完成、待处理、待补图、证据版本及下一批范围。无需另建质量、预审、自测和修补队列。
5. 默认重点复查已确认问题、疑点、易漏区域与报告编号／位置；证据或规范变化时重审受影响记录。无新疑点的正常页不强制重复打开全部原图。用户明确要求严格双轮时才执行全部原图和组件的第二轮；安卓扩展证据模式按其平台契约执行。
6. 对账完整素材 → 候选分类 → 受审状态 → 真实组件检查 → 问题与代表图 → 全部发生页／重复来源映射。未读清、未检查或未解决的范围保持未完成，不能用文件生成、hash 校验或任务 complete 代替视觉验收。完整记录通过平台校验后，由主智能体统一发布并回读实际结果。

图片调用遵循采集 skill 的 image-processing.md 和 image_batches.py：每次默认 1–2 张、最多 2 张，按总像素／尺寸／字节检查，当前批分析保存后才读下一批。候选、原图、细节、复查、官方例图和报告预览共享实际上下文累计账本；接近预算保存进度并在真实新上下文接续，不减少应验收画面。

报告继续使用现有 build_report.py、report-style.json 和输出参考：官方示意 → App 问题示例 → 全部问题页面汇总。三段式顺序、配色、字体、说明卡片、图外编号和短引线、截图比例及完整来源映射均保持现有要求。内部索引／观察文件不进入读者报告；平台特有的问题分类不因流程统一而改变。发布后仍须实际预览检查样式与标注，结构校验不等于视觉完成。

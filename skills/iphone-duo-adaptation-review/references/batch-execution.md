# 集中批量审核

默认回到集中选帧、清晰拼图巡检、疑点原图、批量记录、重点复查和统一报告。检查规则仍使用当前 Apple 规则包；不恢复已纠正的判定、示例或去重错误。

- 全部录屏抽帧并分类候选，核对页面、姿态、窗口及内容状态后保留清晰代表图和完整来源映射。重复画面集中去重，新组件和独立布局状态保留；疑点才补帧。
- 脚本核对来源、尺寸和 hash。巡检清晰整页成品拼图时同时确认选帧质量、裁边／脱敏和适配，不设独立全量人工质检。小候选图用于筛选；字、图标或边界读不清时打开该页原图／细节。
- 每个受审页面均查看全部可见组件，集中保存页面和组件观察。真实观察确定后批量展开 checks、check_items 和 findings；没有看过的项不从问题列表反向填通过。平台布局指导差异与显示缺陷仍分开。
- 复查集中于已确认问题、疑点、易漏区域和报告编号／位置。正常页没有新疑点不强制再次打开全部原图；不要求独立全量第二轮，也不填写未执行的双轮完成标志。用户明确要求严格双轮时再按全部原图执行。
- 最后统一核对覆盖、引用、问题及报告映射，发布后回读。证据更新重审受影响记录；来源缺口如实说明，不包装成通过或确定缺陷。

默认主智能体按业务流程连续工作，抽帧和排版可用脚本并发；独立录屏确有收益才分工。单智能体不建立分工收据，不按每几张图创建执行者。图片调用继续按采集 skill 的预算检查、记账和接续协议进行，拼图保留每页格位、来源及 hash，不把几十页塞进读不清的一张图。

观察及时保存，在流程结束、阶段切换或中断时保存检查点；无需另建质量、自测、预审和修补队列。当前 validate_review.py 核对原图来源、全页逐项记录和报告关系，本就不要求全量第二轮字段；保留此能力，不额外增加双轮门槛。首次生成文件不代表视觉完成。

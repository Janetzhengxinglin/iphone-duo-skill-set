# iPhone Duo 适配审查

总入口：调用 App 录屏页面截图和 iPhone Duo 设计规范，筛选问题页面、归并同类问题、生成并发布报告，交付后总结共性问题。版本 0.2.15。规则仅维护在规范 skill，不复制规则或历史问题清单。

## 执行方式与子智能体

默认主智能体按业务流程集中执行；只有独立材料确有分工收益时才读取 [条件分工与交接](references/agent-coordination.md)。单智能体不维护额外分工收据，主智能体统一覆盖核对与发布。

## 启动检查与交接

首次执行本轮任务前，用处理录屏的 Python 运行本 skill 的 `scripts/preflight.py`，检查三个 skill 的同级安装、支持版本与截图依赖。检查失败先补齐对应 skill 或可用运行环境，不跳过环节、不替换为竞品流程；版本不兼容时安装同一发布包。再运行规范 skill 的 `scripts/validate_rules.py` 核对规则来源完整性。

运行命令时把各 skill 的脚本解析为绝对路径，全部中间数据使用同一个绝对 `RUN_DIR`。截图 skill 写入的完整 `capture.json` 由本入口 `workflow.py seed` 交接为 `review.json`，逐页审查不得丢失页面 ID、证据 ID、姿态或图片校验值。报告只读取该轮审查数据；发布前核对所选 Figma／飞书工具与用户目标权限，缺工具或权限明确说明并保留本轮草稿，不切换发布位置。检查保障安装和数据交接条件，不证明视觉判断准确。

## 交互

读 [交互与任务数据](references/intake.md)。用交互提问工具一次收集缺失的流程名称、姿态、输出位置和报告内容。姿态交互选项统一为“折叠态、展开－横屏、展开－竖屏”；支持混合。后台映射见交互与任务数据，不向用户展示英文标识。输出选择 Figma 或飞书并提供对应目标链接；内容选择“适配缺陷＋平台布局差异”（推荐）或“仅适配缺陷”，两类结论分开。

已有明确值不重复问，预选不是回答。姿态或正式目标缺失可先截图候选，不替用户选择发布位置。内容未明确先询问，用户要求直接开始则用推荐范围。保存 intake.json，`python3 scripts/workflow.py init INTAKE RUN_DIR` 建独立任务。

选择 Figma 输出时，必须由用户提供本轮可编辑的目标文件链接；缺少链接就通过交互提问收集，不沿用历史文件、不自动新建替代目标。已提供则直接沿用，不重复问；写入前核对该文件与编辑权限。

## 截图与审查

按 [集中批量审核](references/batch-execution.md) 执行：

1. 批量抽帧、分类全部候选，集中选择清晰代表状态，保存完整 capture.json 与来源映射。
2. 按流程巡检清晰整页成品拼图，同时确认选帧质量、脱敏和适配；读不清或有疑点才打开原图，集中记录全部页面／组件观察并生成正式记录。
3. 重点回查问题、疑点、易漏区域及报告位置，不默认要求独立全量质检或第二轮全部原图复读。
4. 统一归组、编号、核对全部发生页面，发布并回读。严格双轮仅在用户明确要求时执行。

审查中确需补图时，返回截图阶段生成修订后的完整清单；保留已有截图、编号和审查结果，核对新增或替换的证据，补审新增状态并复审受替换证据影响的结论。不得静默改图后继续沿用旧结论。不得把本次页面数量或页面名写入 skill。

读取同级 `../app-video-page-capture/SKILL.md`，不调用竞品 skill，不增加竞品审批关卡。完成 capture.json 后用 `python3 scripts/workflow.py seed RUN_DIR` 转换为 review.json 初始证据；此脚本不识别组件，不预填通过。

读取 `../iphone-duo-design-guidelines/SKILL.md` 和 capture-handoff，逐页按姿态完成规则筛选、组件实例清单、checks 与 check_items。每个受审状态都有结论；判断仅基于截图，不推断未展示行为。规范 validate_review.py 校验全部记录。

后台保留全部截图和审查结果。报告展示 issue，以及用户选择包括的 guidance_deviation；指导差异不计必须修改。未发现时只简短结论，不空造问题画板。不明候选查相关官方原文和例外，缺依据不列问题，不用“待核实”等页面标签代替判断。

## 汇总与输出

发布前必须读取 [视觉呈现与验收](references/output-presentation.md)，落实简短说明、抽象对应图解、统一对齐、就近图外标号、适中参考尺寸和底部全量去重映射；该文件优先约束展示方式，不改变平台判定规则。

问题数量、单页问题数量、问题类型数量及问题页面数量均无上限。所有适用页面检查完成后再归组；同类合并说明但保留全部发生页面和问题位置，不按历史类别或模板容量截取发现。

读 [报告约定](references/report.md)。按本次发现归组，同组跨页同编号，不固定历史类型。固定为官方规范示例在前、App 问题示例与集中说明在后、最后一个问题页面汇总；每组一次短说明，代表图跨组去重，可用多张覆盖全部现象。官方示例先选对应的官方抽象图解，再按需要查 HIG 页面、经核实的苹果 UI Kit 结构 Frame 和官方视频，匹配本次姿态与问题；保持原始内容，不加工；规范区与问题区分别使用醒目的标题。问题标注位置来自本次 App 截图。

`python3 scripts/build_report.py RUN_DIR` 校验完整覆盖与证据，生成 report.json、可编辑 Figma 标注数据、Lark 原生块排版稿、标注图片和内部 HTML。它不判断、不发布。样式独立在 assets/report-style.json；三种姿态使用同一套排版、字体、说明卡颜色和编号样式，只按原图比例调整截图高度。问题示例默认每编号一张代表图，必要时补图覆盖新组件或独立位置；底部按人工核实的同页分组去重，完整来源留后台。训练样式不改规范。

按用户选择只读 [Figma 输出](references/figma-output.md) 或 [飞书输出](references/lark-output.md)，使用对应工具完成写入和回读。Figma 中的官方 UI Kit 示例优先复制／导入原生 Frame 或组件实例，保留内部图层；图片仅用于预览、飞书或经核实复制受限后的替代。按 Figma 输出的验收要求检查内部可编辑性，不能把图片外套 Frame 算作原生示例。内部 HTML 不替代选定交付。失败保留草稿、明确未发布；保存 publication.json 的目标链接、版本、节点/块映射和报告校验值。

交付只含页面名/必要状态、问题类型、问题点、可点击官方依据；不露截图 ID、时间点、重复索引、执行指令、配置疑问、制作过程。目视核对比例、两侧编号、引线、文字间距、链接、展示页确有对应发现。新版本保留历史报告。

## 交付后共性问题总结

报告发布并回读通过后，按 [共性问题总结](references/common-problems.md) 在当前聊天中简短总结本轮重复出现的客观问题，给用户选择是否另建飞书共性问题文档。该文档按“大类｜共性问题表现｜图片示例｜官方依据与修改建议”组织；不推测开发习惯或代码原因，不重复主报告。没有共性问题时简短说明即可。总结与用户选择留在本轮任务目录，不写入 skill。

## 每轮复盘与持续改进

每次审查结束按 [持续改进](references/continuous-improvement.md) 汇总截图、判断、自测和交付阶段的问题，保存项目级 retrospective.json。发现普适方法缺口时，经原图/来源核实和正反案例验证，备份并更新负责该环节的 skill，再回查受影响结果。没有被证据支持的通用改进时记录即可，不强行修改。用户后续纠错也纳入该轮复盘，并在发布修订前复查。具体素材与案例留在项目目录，skill 仅保留可复用方法；向用户简短汇报实质变更。

## 图片读取与分批接续

执行各阶段前读取 [图片处理协议](../app-video-page-capture/references/image-processing.md)，完整清单在本地交接，图片分批读取并保存累计日志和检查点。默认保持全页清晰巡检和问题重点回查，汇总及发布预览也纳入图片预算。

按采集 skill 的图片协议执行读取前预算检查、记账和接续。读取批次不拆成独立工作任务；原图用于疑点及问题回查。

统一执行方法见 [批量执行](references/batch-execution.md)；验收覆盖与现有三段式报告样式不变。

# 图片筛选、读取预算与接续

这是模型输入的执行规则，不改变平台规范、受审范围或阶段顺序。安卓和苹果维护相同的方法；本轮素材、读取日志和检查点只保存在任务目录。

## 候选筛选

sample 保留原视频、全部候选及时间索引，默认只折叠连续完全相同的候选。苹果使用全分辨率解码像素与尺寸的 hash，安卓使用完整无损 PNG 的 hash；不使用缩略图变化分数、相似度或机型猜测自动剔除。每段保留首尾代表帧；不同尺寸、不同画面、非连续的相同画面和缺 hash 的候选不折叠。--keep-all-candidates 可恢复全部候选拼图。

按 candidate-groups.json 的 sheet_candidate_ids 顺序看拼图，并用 groups 展开为全部原候选 ID 后填写分类。被折叠的帧仍在候选清单中；分组不等于已完成视觉分类、区间覆盖或页面去重。重复画面可能对应不同操作和业务上下文，仍核对时间间隔与来源；细节不清、短暂状态、快速变化或疑似遗漏时补看候选原图／原视频并加密该区间，不凭稀疏采样宣布不存在。保持默认采样密度；只在区间补查，不为降低图片量全程放疏采样。

候选优先通过拼图识别，只有需要确认细节时单独打开。非 App 画面、转场和无意义重复加载按原采集规则分类；键盘、菜单、弹层、错误、不同布局滚动状态、姿态／窗口和有独立布局的加载状态保留。拼图仅作筛选与定位，不能代替清晰原图的规范判断。

## 减少重复输入

保留所有证据文件。原图与受审图未作裁边／脱敏且内容、尺寸一致时，质量核对只读取其中一份；有处理差异则对照受影响部分。候选分类时已经看过的图片不在同阶段无理由重读；需要复查时仍可读取，并计入预算。局部图按具体疑点生成，保持原图和坐标映射，不默认给每页生成多张。第二轮必须重新查看全部受审页面，不得用同阶段去重跳过复查。

## 分批和累计预算

默认每次工具返回图片不超过 6 张，同一聊天累计观察到约 30 张图片时保存接续检查点；这是可调整的保守执行预算，不是模型统一上限或不超限保证。实际请求可能还携带用户附件、历史图片及其他工具预览。把拼图、单帧、局部图、官方示例和报告预览都计入；重复读取也计数。不能只统计受审页面数。

图片清单使用 JSON 路径数组，由 scripts/image_batches.py plan MANIFEST OUTPUT --batch-size 6 输出纯文字批次。图片实际返回后，调用 scripts/image_batches.py record LEDGER --session CHAT_ID --stage STAGE --image IMAGE（多图重复 --image）；--call-limit 和 --session-limit 可调整。脚本只记录观察到的输入和提示，不控制客户端历史，也不自动触发读取、审查或新聊天。更换批次、等待、文字摘要或改写 session 名称都不能清除请求历史；只有真实的新上下文才能使用新的 session。

接近预算或发生图片超限时保存进度，停止原样重试。如需用户切换聊天，提供交接文件和接续指令；不声称已经自行清空上下文，不用继承完整历史的分叉代替新上下文。

## 阶段与检查点

完整截图整理及质量回查 → 完整清单交接 → 第一轮全部页面审查 → 第二轮全部页面原图复查 → 统一汇总与发布回读。每个阶段内部可以分批；全部图片准备好指本地文件与清单齐全，不要求一次输入模型。覆盖数量和问题数量不受读取预算限制。

每批保存已有阶段结果，在 image-checkpoint.json 记录：规则与清单版本／hash、当前阶段、完成和待处理页面／证据 ID、第一轮与第二轮各自完成范围、图片路径／hash、待补图与待确认事项、下一批范围、读取日志路径、输出目标及发布节点／块映射（如有）。安卓沿用 review-input.json 与 review.json；苹果沿用 review.json 和 review-self-test.json；截图阶段沿用各自完整分类格式，不改交接 schema。接续先核验文件及 hash，恢复未完成项，不仅凭摘要宣告完成。

保存 image-usage.json，按阶段汇总候选数、代表数、拼图输入、单帧输入、局部图、重复输入和已完成受审状态。采样生成文件数不等于模型输入图片数。完成前按完整清单核对全部受审状态两轮检查和报告覆盖，不把脚本通过、少量图片或读取量下降当作审查准确性证明。

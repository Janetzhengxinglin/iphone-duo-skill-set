# 图片筛选、读取预算与接续

这是模型输入的执行规则，不改变平台规范或受审范围。图片预算与完整性方法沿用既有约定；Duo 的阶段调度另见 [批量执行](../../iphone-duo-adaptation-review/references/batch-execution.md)。本轮素材、读取日志和检查点只保存在任务目录。

## 验收完整性优先

图片预算只约束每次读取量，不限制需要验收的画面数量。预算与验收覆盖冲突时，拆批并接续处理，不减少范围、不降低清晰度、不用抽查代替全量验收。不得因视频时长、图片数量、已发现问题数量或上下文不足，跳过应保留的页面、姿态、窗口、内容状态或组件。

候选拼图折叠只是呈现优化，不自动删除候选、不自动认定业务状态重复，也不生成通过结论。只有核对完整画面、姿态／窗口、内容状态和业务上下文均相同，并保留候选 ID 到代表证据的映射，才能把连续重复帧归入同一受审状态。无法确认时展开相关候选／区间核实，并在完成核实前保留为待处理项。不能以像素 hash 相同直接认定两个业务状态无需分别验收。

建立完整应验收状态清单后，默认每页均须在清晰整页成品拼图或原图中巡检，读不清的文字、图标、边界和疑点打开原图／细节；同时核对截图质量和组件。完成后回查已确认问题、疑点和报告映射，不强制全部原图再读两遍。严格双轮才另做第二轮全部原图及组件复查。

完成前对账全部巡检页面、真实组件观察、证据版本和问题映射；未看的页、未解决的读图缺口保持未完成，不把生成图片或脚本通过当视觉检查。记录实际使用的策略，不填并未执行的双轮标志。

## 候选筛选

sample 保留原视频、全部候选及时间索引，默认只折叠连续完全相同的候选。苹果使用全分辨率解码像素与尺寸的 hash，安卓使用完整无损 PNG 的 hash；不使用缩略图变化分数、相似度或机型猜测自动剔除。每段保留首尾代表帧；不同尺寸、不同画面、非连续的相同画面和缺 hash 的候选不折叠。--keep-all-candidates 可恢复全部候选拼图。

按 candidate-groups.json 的 sheet_candidate_ids 顺序看拼图，并用 groups 展开为全部原候选 ID 后填写分类。被折叠的帧仍在候选清单中；分组不等于已完成视觉分类、区间覆盖或页面去重。重复画面可能对应不同操作和业务上下文，仍核对时间间隔与来源；细节不清、短暂状态、快速变化或疑似遗漏时补看候选原图／原视频并加密该区间，不凭稀疏采样宣布不存在。保持默认采样密度；只在区间补查，不为降低图片量全程放疏采样。

候选优先通过拼图识别，只有需要确认细节时单独打开。非 App 画面、转场和无意义重复加载按原采集规则分类；键盘、菜单、弹层、错误、不同布局滚动状态、姿态／窗口和有独立布局的加载状态保留。小候选拼图仅作筛选与定位；清晰整页成品拼图可巡检，读不清及疑点必须打开原图。

## 减少重复输入

保留所有证据文件。原图与受审图未作裁边／脱敏且内容、尺寸一致时，质量核对只读取其中一份；有处理差异则对照受影响部分。候选分类时已经看过的图片不在同阶段无理由重读；需要复查时仍可读取，并计入预算。局部图按具体疑点生成，保持原图和坐标映射，不默认给每页生成多张。默认不要求无疑点的正常页重读；严格双轮第二轮仍重新查看全部受审原图。

## 分批和累计预算

默认每次读取 1–2 张，最多 2 张；刚开始任务、当前对话很长或图片较大时先读 1 张。一次读取指本次执行向模型返回的全部图片，不按工具、并行调用或拼图分别放宽。读取期间按批顺序执行，完成判断、保存本次观察及预算日志后才读取下一批；关联组结束或中断时保存汇总检查点。禁止循环／并行一次返回所有批次。

读取前先在本地检查本批图片数量、尺寸、总像素与文件大小，只返回文字结果。默认本批总像素不超过 4,000,000、单图最长边不超过 2560、总文件大小不超过 8 MiB。这些数值是可调的本地保守预算，不是平台限制或不超限保证；文件压缩变小不代表解码像素变少。成品拼图保留清晰整页格位和源图映射；按像素与可辨性拆分，不把几十页塞成读不清的一张图。

候选拼图可缩小或拆成多张，保留完整候选与时间映射；默认可使用清晰整页成品拼图巡检；疑点和问题定位使用原图。超大原图先保留整页定位，再分批读取有重叠的原尺寸细节图，记录覆盖区域；不能用模糊缩略图代替原图判断或丢掉未展示区域。确需超出尺寸预算读取清晰整页原图时，应单张试读，记录理由和显式参数；不因赶进度提高每次张数。

累计观察／尝试输入约 30 张时停止继续读图，保存接续检查点。把用户附件、候选拼图、单帧、局部图、官方示例、报告预览和重复读取都计入同一实际上下文；未知历史输入量或已明显接近上下文限制时提前停止。工具文字输出也只返回当前批范围与必要结论，大清单、完整 JSON 和详细日志留在本地。新批、等待、文字摘要、修改 session 名称或继承完整历史的分叉均不清空历史；只有真实新上下文才能用新的 session。

### 必须执行的读取前检查

同级采集 skill 的 scripts/image_batches.py 用于本地计划、检查和记账。图片清单使用 JSON 路径数组；所有命令输出纯文字，不向模型返回图片。

~~~bash
python3 scripts/image_batches.py plan MANIFEST BATCH_PLAN --batch-size 2
python3 scripts/image_batches.py check LEDGER BATCH_MANIFEST --session CHAT_ID --stage STAGE
# 只有 ready=true 后，才用图片工具读取该批；BATCH_MANIFEST 仅包含本批路径。
python3 scripts/image_batches.py record LEDGER --session CHAT_ID --stage STAGE --image IMAGE
# 若读取请求超限／拒绝，记录失败，不写已审查或通过：
python3 scripts/image_batches.py fail LEDGER --session CHAT_ID --stage STAGE --image IMAGE
~~~

多图重复 --image。plan 保留全部路径，并按数量与像素预算拆批；单张超出预算仍保留在计划中，标记 blocked，处理尺寸或单张例外后重新检查。check 的拒绝以非零退出码返回；脚本不能拦截其他工具，执行者必须依据结果控制实际读图。读取后 record；失败后 fail，日志不等于审查记录。--call-limit、--session-limit、--max-pixels、--max-edge、--max-bytes 可调整，调整原因写入检查点；没有观测依据不得把平台上限写成确定数值。

### 超限后的停止与降量

首次超限立即保存失败批次与进度，默认切换单张；缩小候选预览或拆开拼图／细节图，再进行读取前检查。禁止原样重试同一失败图片组合，禁止原样反复试整页大图。失败后默认单次像素预算减半；脚本拒绝原样失败组合，失败输入按保守尝试量计入累计预算，因为是否进入客户端历史未知。

同一实际上下文累计两次失败、达到累计预算，或单张调整后仍无法读入时，停止继续输入图片，保存 image-checkpoint.json 和接续指令。未完成状态继续保留为待处理，不删图、不减少覆盖、不宣告全量审查完成。能真实切换上下文则接续；需用户开新聊天时提供文件路径与接续说明，不能假称已经自动重置。

## 阶段与检查点

批量采样与候选分类 → 清晰成品拼图全页巡检（同时确认质量及适配）→ 疑点原图补查 → 批量生成记录 → 问题和报告重点复查 → 统一校验、发布回读。严格双轮按其全量双轮要求执行。观察及时保存，流程结束、阶段切换或中断时保存检查点。
每次图片调用后保存真实观察及预算日志，关联组结束或中断时在 image-checkpoint.json 记录：规则与清单版本／hash、当前阶段、完成和待处理页面／证据 ID、全页巡检和重点回查范围（严格双轮另记两轮范围）、图片路径／hash、待补图与待确认事项、下一批范围、读取日志路径、输出目标及发布节点／块映射（如有）。Duo 使用 capture.json 与 review.json 保存实际观察；截图阶段沿用各自完整分类格式，不改交接 schema。接续先核验文件及 hash，恢复未完成项，不仅凭摘要宣告完成。

保存 image-usage.json，按阶段汇总候选数、代表数、拼图输入、单帧输入、局部图、重复输入和已完成受审状态。采样生成文件数不等于模型输入图片数。完成前按完整清单核对全部受审状态巡检、所选策略复查与报告覆盖，不把脚本通过、少量图片或读取量下降当作审查准确性证明。
